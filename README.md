# PS5 Monitor

Личный мониторинг дисковых PS5 в немецком магазине PlayStation: Telegram-уведомления и веб-панель на русском языке. Python 3.11+, без сторонних библиотек, базы данных и платного сервера.

Панель после публикации: https://mmur1n.github.io/ps5-monitor-2/

## Бесплатный запуск

1. Репозиторий должен быть **публичным**. Стандартные Linux runners GitHub Actions и GitHub Pages в публичном репозитории бесплатны. В закрытом репозитории workflow намеренно не запускается, чтобы не расходовать платные минуты.
2. В Settings → Pages выберите Source: **GitHub Actions**.
3. В Settings → Secrets and variables → Actions → New repository secret добавьте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. В CHAT_ID укажите числовой ID личного чата, без @. Не сохраняйте токен в коде, Issues, Variables или истории команд.
4. Отправьте своему боту `/start`. Бот не может первым начать личную переписку.
5. В Actions → PS5 stock monitor → Run workflow запустите проверку с `test_telegram: true`. Должно прийти сообщение о подключении, а в панели появятся товары.

Расписание — каждые 5 минут, со смещением от начала часа. Компьютер можно выключить. GitHub может задерживать или пропускать запуски при высокой нагрузке: это не гарантия проверки ровно каждые 300 секунд.

## Какие товары отслеживаются

Весь каталог страницы https://www.playstation.com/de-de/consoles/ps5/shop-all/, включая страницы после «Mehr anzeigen». Автоматически находятся новые дисковые консоли и комплекты. Digital, PS5 Pro без дисковода и отдельные дисководы исключены. Восстановленные дисковые консоли включены и отмечены; их можно скрыть в панели.

Карточка загружается заново при каждом запуске. Сопоставляются данные именно выбранного товара, запас SKU, inventoryOverride и CTA покупки. `IN_STOCK` вместе с `UNAVAILABLE` показывается как «Покупка недоступна»; такое противоречие не вызывает уведомление. Предзаказ показан отдельно. Неизвестный формат или блокировка сайта становятся ошибкой проверки, а не наличием. Маркетинговый текст и JSON-LD `InStock` сами по себе не служат доказательством.

В Telegram отправляется первое подтверждённое наличие и каждый переход обратно в наличие. Ошибки проверки не сбрасывают последнее надёжное состояние. Неудачные отправки повторяются при следующей проверке, пока товар доступен. После внезапного завершения процесса между отправкой и сохранением возможен повтор: Telegram не предоставляет идемпотентность `sendMessage`.

## Панель и хранение

Статусы хранятся в ветке `monitor-data`, последние 120 изменений — в `state.json`. Ветка `main` содержит только код. Панель обновляет сохранённые данные раз в минуту; кнопка «Обновить данные» перечитывает результат, а не запускает скан магазина. Для ручной проверки используйте Actions → Run workflow.

В публичные данные не записываются токен, chat ID, сообщения пользователей или ответы Telegram. Секреты доступны только шагу отправки. Ошибки Telegram выводятся без адресов запросов и без содержимого ответов. В workflow нет pull_request_target или запуска кода из сторонних PR с секретами.

При недоступности источника последние результаты сохраняются. Панель предупреждает о сбое и о данных старше 20 минут. Ошибка источника или Telegram помечает запуск Actions как неуспешный, но обновлённая панель всё равно публикуется.

## Локальный запуск и проверка

```sh
python3 -m unittest discover -s tests -v
python3 -m monitor.run --no-telegram
python3 -m http.server 8080 --directory web
```

Откройте http://localhost:8080. Для локальной отправки передайте два секрета через переменные окружения. `.env` автоматически не читается и исключён из Git. `python3 -m monitor.run --test-telegram` отправляет проверочное сообщение.

Если Sony изменит формат каталога, монитор попробует обновить хеш запроса из официальных скриптов. Если изменится структура карточек или тип CTA, потребуется обновить `monitor/source.py`; до этого неизвестные состояния не вызовут ложных уведомлений. Для поиска проблем смотрите Actions и предупреждения панели. Если расписание отключено GitHub из-за длительного отсутствия активности, включите workflow снова в Actions.

Официальная документация: [биллинг Actions](https://docs.github.com/en/actions/concepts/billing-and-usage), [расписание и задержки](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule), [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages), [Telegram Bot API](https://core.telegram.org/bots/api).

Независимый личный проект. Наличие не резервирует товар; окончательная доступность проверяется в магазине.
